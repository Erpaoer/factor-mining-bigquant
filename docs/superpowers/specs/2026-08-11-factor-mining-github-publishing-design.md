# Factor Mining BigQuant：GitHub 精简发布设计

## 1. 目标

将当前研究目录整理为一个便于阅读、克隆和继续维护的私有 GitHub 仓库，同时保留本地完整研究资料。远端仓库只收录核心因子库、必要文档和少量代表性 Notebook，不上传大体积研究输出。

目标仓库配置：

- 所有者：`Erpaoer`
- 仓库名：`factor-mining-bigquant`
- 可见性：Private
- 默认分支：`main`
- README：中文为主，保留必要的英文类名、函数名和量化术语

## 2. 当前项目概况

整理前目录约 121.6 MB，共 183 个原始文件，主要包括：

- 48 个 Python 文件，约 17,768 行代码；
- 30 个 Jupyter Notebook；
- 102 张 PNG 研究结果图；
- `factor_lib` 中登记的 28 类因子，其中 27 类为普通因子，1 类为 GAN-GRU 机器学习因子；
- 因子复现、单因子分析、候选因子聚类、多因子策略与 BigQuant 教程资料。

本地检查已确认：

- 48 个 Python 文件均可通过语法解析；
- 27 个普通因子已通过本地合成数据冒烟测试；
- 上述检查不等价于在 BigQuant 平台完成真实数据回测；
- 3 个 Notebook 含有已保存的错误输出，不纳入推荐示例集。

## 3. 发布范围

### 3.1 收录内容

远端仓库收录：

1. 根目录 `README.md`；
2. 精简后的 `.gitignore`；
3. `factor_lib` 下的全部 Python 源码；
4. `factor_lib/README.md` 技术说明；
5. 本设计说明及后续实施计划；
6. 以下 5 个轻量且未保存错误输出的代表性 Notebook：
   - `我的文档/8.因子分析.ipynb`：BigQuant 因子分析流程；
   - `研究稿/华泰因子复现/华泰估值类因子/BP因子/BP因子.ipynb`：估值因子示例；
   - `研究稿/华泰因子复现/华泰财务质量因子/qfa_roe因子/qfa_roe.ipynb`：财务质量因子示例；
   - `研究稿/华泰因子复现/华泰成长类因子/Profit_G_q因子/Profit_G_q.ipynb`：成长因子示例；
   - `模拟策略/exp_wgt_return_6m防御性+收益补偿.ipynb`：模拟策略示例。

### 3.2 排除内容

远端仓库不收录：

- 其余 25 个 Notebook，尤其是 5–27 MB 的大型研究文件；
- 102 张 PNG 结果图以及其他研究导出图片；
- `__pycache__`、`.pyc` 等运行缓存；
- 编辑器、操作系统临时文件；
- 可能包含凭据的本地配置、环境变量文件和密钥文件；
- 当前没有明确、可复现依赖版本的情况下，不生成猜测性的 `requirements.txt`。

排除仅通过 Git 忽略规则和精确暂存实现，不删除或移动本地原始资料。

## 4. README 信息架构

根 README 采用“先说明是什么，再说明怎么用”的结构：

1. 项目简介与适用场景；
2. 核心能力概览；
3. 项目结构与精简发布说明；
4. 因子类别和 28 类因子索引；
5. BigQuant 环境依赖和导入方式；
6. 最小使用示例；
7. 代表性 Notebook 导航；
8. 已完成的本地验证；
9. 已知限制，包括平台依赖、接口文档差异和真实回测仍需复核；
10. 研究用途及非投资建议声明。

README 不承诺未验证的收益表现，不把合成数据冒烟测试描述成真实市场回测。

## 5. Git 与发布策略

1. 在本地以 `main` 初始化 Git；
2. 先单独提交本设计说明，形成可审查的决策记录；
3. 根据批准后的实施计划修改 README 和忽略规则；
4. 对待发布文件进行凭据扫描、语法检查、Notebook JSON 检查和范围核对；
5. 精确暂存收录文件，确认没有大型 Notebook、图片或缓存进入提交；
6. 创建 `Erpaoer/factor-mining-bigquant` 私有仓库；
7. 将 `main` 推送至 `origin`；
8. 从 GitHub API 复核仓库可见性、默认分支和远端提交。

首次发布直接建立私有仓库主分支，不额外创建无意义的 Pull Request。

## 6. 安全与质量检查

发布前必须完成：

- 对待提交文本及 Notebook 源内容扫描常见 Token、密码、私钥和连接串模式；
- 检查 Git 跟踪清单，确保排除项未被暂存；
- 检查所有被跟踪文件大小，确保不存在接近 GitHub 100 MB 单文件限制的文件；
- 使用不生成新缓存的方式解析全部 Python 源码；
- 验证 5 个示例 Notebook 均为有效 JSON，且没有已保存的 `error` 输出；
- 检查 README 内部链接指向实际被跟踪的文件；
- 推送后使用 GitHub CLI 验证 `visibility=PRIVATE`、默认分支为 `main`，且远端提交与本地 `HEAD` 一致。

扫描结果只报告文件位置和问题类型，不输出任何完整凭据值。

## 7. 已知限制

- 代码依赖 BigQuant 数据接口和运行环境，不能保证在普通本地 Python 环境中直接完成真实数据计算；
- `factor_lib/README.md` 中存在部分历史导入路径或接口描述与当前源码不完全一致的情况，根 README 将以当前源码结构为准并明确提示；
- 个别因子方向约定和 T/T+1 回测语义仍应在 BigQuant 平台用真实数据复核；
- 本次任务只负责整理与私有发布，不修改因子算法，也不声称策略具有未来收益能力；
- 私有仓库暂不添加开源许可证。

## 8. 验收标准

完成时应同时满足：

- GitHub 仓库 `Erpaoer/factor-mining-bigquant` 已创建且为 Private；
- 默认分支为 `main`；
- 根 README 能准确说明项目用途、使用方式、验证边界和风险；
- 48 个 Python 源文件及指定的 5 个 Notebook 已被跟踪；
- 大型 Notebook、研究图片和缓存文件未进入远端仓库；
- 待提交内容未发现明文凭据；
- 本地与远端最新提交一致。
